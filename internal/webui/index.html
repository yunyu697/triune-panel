规则集

勾选需要的规则集并指定策略（DIRECT 直连 / PROXY 代理 / REJECT 拦截）。 默认策略按规则集推荐值带出：国内站点 / 私有网络 DIRECT、广告与追踪 REJECT、境外服务 PROXY，勾选后仍可逐条改。 每个分组标题右侧有本组「全选 / 清空」；顶部的「全选 / 清空」作用于当前搜索结果。 两者都会自动跳过本内核不可用的规则集——标记「仅 mihomo」「仅 singbox」的规则集在另一内核的上游并不存在，切换内核时会自动置灰。

自定义规则

每行一条，语法 类型,值,策略，策略可选 DIRECT / PROXY / REJECT。
类型：DOMAIN、DOMAIN-SUFFIX、DOMAIN-KEYWORD、IP-CIDR、IP-CIDR6、GEOSITE、GEOIP。
示例：DOMAIN-SUFFIX,example.com,DIRECT、IP-CIDR,1.2.3.0/24,PROXY、GEOSITE,bilibili,DIRECT

基础设置

        

          

          

          

          
留空可前往下方「组件更新与版本管理」一键安装面板专用副本到 data/bin/，与系统其他服务互不影响。

          

          

            

          

          

            

            

          

          

            

        

        

          可信反向代理网段：面板挂在 nginx / Caddy 后面时必填（同机填 127.0.0.1），
          否则登录来源一律是代理 IP，防爆破会变成「一个人输错五次，所有人一起被锁」。
          仅当直连对端落在这些网段内才采信 X-Forwarded-For / X-Real-IP；留空 = 不信任任何代理。
        

        

          指标访问令牌：填了才会开启 /metrics（Prometheus 格式），采集时用
          Authorization: Bearer <令牌>。留空 = 该端点关闭（返回 403），
          避免升级后凭空多出一个「知道地址就能看用户列表和流量」的接口。
        

        

          
        

        

          
        

        
仅管理本机防火墙，云厂商安全组需在控制台另行放行。iptables 规则重启后不保留，ufw / firewalld 会持久化。

          改配置时推一条摘要出去：谁、什么时候、改了什么，设置项带字段级 diff（从什么改成什么）。
          邮件复用下方「登录二次验证」里的 SMTP 通道；Webhook 是 POST 一个 JSON。
          敏感值（密码 / 密钥 / 令牌）只写「已变更」，不推明文。

登录二次验证（2FA）

        
在账号密码之外追加一道验证。开启后登录需输入第二步凭据，验证失败同样计入防爆破锁定。两种方式二选一。

        

          

            方式一：验证器 App（TOTP 动态口令）
            
Google / Microsoft Authenticator、1Password、FreeOTP 等均支持。绑定：验证器 App → 手动输入密钥（需设备时间准确）。

            

              

                

                

                

              

              

                
                
              

            

            
          

          

            方式二：邮箱验证码
            
登录时向下方邮箱发送 6 位验证码（5 分钟有效）。需配置可发信的 SMTP 通道。

            

              

              

              

              

              

              

            

            

              
              
            

          

        

        

          
        

      

      

        
面板自更新

        
当前版本 。更新流程：下载 → 可执行验证 → sha256 校验 → 备份旧文件 → 原子替换 → 无缝重启，数据与配置不受影响。

        

          

          

        

        
        
        
      

      

        
组件更新与版本管理

        
面板与三个内核均可更新/降级到任意版本。每一步都有安全保护：新二进制可执行验证 → 用它校验当前配置 → 备份旧版本 → 原子替换 → 重启 + 健康检查，任一环节失败自动回滚，服务不中断。
